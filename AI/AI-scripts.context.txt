## Зачем
Bash-скрипты для медиа на macOS. Сюда только инструменты; готовые файлы — в библиотеки владельца.

Приоритет: **видео фильмов** (контейнер + дорожки, звук внутри файла). Чистый аудио и картинки — позже; не путать sound-in-video с отдельным mp3.

## Раскладка
| Путь          | Зачем                                              |
| ------------- | -------------------------------------------------- |
| `bin/`        | запускаемые скрипты (kebab-case: `to-mp4`, …)      |
| `lib/`        | общие куски shell, если появятся                   |
| `inprogress/` | временные медиа; после работы очищать              |
| `specs/`      | ТЗ: `specs/<script-name>.txt`                      |
| `AI/`         | этот context + `WIP.txt`                           |
| `.cursor/`    | slash-команды проекта                              |
| корень        | `README.md`, `.gitignore`                          |

Флоу: медиа в рабочей папке (часто `inprogress/`) → скрипт из `bin/` ищет файлы в **текущей папке запуска** → выход **рядом с исходником** → готовое уезжает в библиотеку; `inprogress/` очистить.
Сессии-подпапки в `inprogress/` — позже, если понадобится.

`AI/WIP.txt` — текст «на чём остановились»; не путать с `inprogress/` (байты).

## Как писать код
- Bash (или zsh-совместимый), имена в `bin/`: **kebab-case**.
- Минимализм: только запрошенное; без лишних проверок и комментариев, если не просили.
- Утилиты под macOS; не ломать оба Mac без явного согласия.
- Медиа не складировать в репо как библиотеку (`.gitignore` уже режет типичные контейнеры).
- Общее — в `lib/`, когда реально понадобится дублирование.
